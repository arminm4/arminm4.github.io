# Project: StudyMate v2: grounded answers from your documents

Extend v1 so users can upload documents (PDF, Markdown, TXT) to a conversation or a personal library, and get answers grounded in them, with citations they can click and verify.

### Requirements

**Ingestion**
- Upload endpoint with type and size validation. Store the original file (local disk or S3-compatible storage such as MinIO).
- A background ingestion job (a simple worker or FastAPI BackgroundTasks for now; Redis queues come in week 10). Statuses: pending/processing/ready/failed, shown in the UI.
- Extract → chunk (structure-aware, with section headers) → hash → embed only new chunks (batched) → upsert into `chunks` with pgvector → delete stale chunks.

**Retrieval and generation**
- Standalone query rewriting for follow-ups.
- Hybrid search in SQL (pgvector + tsvector with RRF), **always filtered by owner** (and by conversation when scoped).
- Optional reranker. Select 4–6 chunks within a token budget.
- A prompt with numbered sources. Citation verification (unknown IDs, uncited sentences). An abstention path.
- Structured output where appropriate (e.g. a "quiz me" feature that returns JSON questions validated against a schema).

**UI**
- Document library with statuses; drag-and-drop upload with progress.
- Citation chips that open the source passage (title, page or section, highlighted text).
- "Answer only from my documents" toggle.

**Evaluation**
- A golden retrieval set (at least 30 questions over your sample documents, including 5 unanswerable). Report recall@5, MRR and p95 latency for dense vs hybrid (vs reranked).
- 20 answers manually reviewed for faithfulness, with a short write-up of the failure types.

## Milestones

- [ ] Upload endpoint + file storage + document table with statuses

## Stretch goals

- Contextual chunk headers generated by a cheap LLM (Anthropic's contextual retrieval). Measure the recall gain.
- Per-document summaries, used for coarse-to-fine retrieval.
